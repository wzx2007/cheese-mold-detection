# 03 · 模型与训练

两个模型共享同一份数据划分文件 `data/processed/split.json`（由 `make_splits.py` 生成），因此结果可直接对比。

## 3.0 数据划分

```
全部 1684 样本 / 830 张原图
├── 测试集 20%：166 张原图 → 338 样本（169 正常 / 169 发霉）
└── 训练集 80%：664 张原图 → 1346 样本（673 正常 / 673 发霉）
        └── 单折抽检时再从中留出 133 张原图（约 270 样本）作验证
```

- `GroupShuffleSplit(test_size=0.2)` 按 **原图** 分组
- 同一张原图切出的 2–4 个 crop 永远在同一侧 → **无同源泄漏**
- 测试集只在最后评估一次

**训练协议：一次训练到位，不做 K 折。** 完整流程是：

1. **单折抽检**：用 531/664 张原图训练、133 张验证，跑一次 24 轮，确认配置可行并看最优点落在第几轮；
2. **全量重训**：在全部 664 张原图（1346 样本）上按事先固定的 26 轮重训一次，余弦退火走完就停，**不按测试集挑 epoch**；
3. **测试集评估一次**，出最终数字。

这么做的原因是算力：单折一轮约 50 秒，5 折 × 34 轮约 2.5 小时。代价是**没有折间方差估计**——无法回答"换一批原图准确率会波动多少"。这一点在 [`04-results.md`](04-results.md) 里被明确列为最大缺口。

> 无论单折还是多折，**按原图分组**这件事都必须做：随机划分会让同一张照片的两个 crop 分落测试集与训练集两侧，准确率被系统性抬高几个点。分组划分的数字更保守，也更接近真实部署。

## 3.1 主模型：CheeseNet-v3（先验引导的紧凑 CNN）

### 输入表示：4 通道

第 4 通道是**霉菌响应图**，把领域先验显式喂给网络：

$$
m=\text{clip}\Big(0.55\cdot\frac{\overline{b^*}-b^*}{32}+0.30\cdot\Big(1-\frac{S}{\overline{S}+25}\Big)+0.40\cdot\frac{\overline{L}-L}{55},\,0,\,1\Big)
$$

物理依据是：**奶酪表皮偏黄（Lab $b^*$ 高），污染霉菌偏绿 / 青 / 灰黑（$b^*$ 低、饱和度低、亮度低）**。三项分别对应"比整体更不黄""更不饱和""更暗"，权重由人工设定。

这个通道与传统方法用的是**同一个**先验（`train_classic.mold_map`），所以两条路线共享同一份领域知识——比的不是"谁有先验"，而是"先验之后怎么办"：手工阈值化 + 形态学统计，还是端到端学习。

### 结构

```
输入 4×224×224
stem  : Conv3×3/s2 (24) → BN → SiLU                    112×112
block1: [Conv3×3 + Conv3×3] (48)   /2                    56×56
block2: [Conv3×3 + Conv3×3] (96)   /2                    28×28
block3: [Conv3×3 + Conv3×3] (160)  /2                    14×14
block4: [Conv3×3/d2 + Conv3×3/d2] (192)  stride 1        14×14
head  : concat( GAP , GMP ) → Dropout(0.2) → Linear(384→2)
```

约 **1.14 M 参数**，**从零训练**（不加载 ImageNet 预训练——产线部署环境常常没有外网、没有 GPU，且 ImageNet 的语义与"奶酪表皮的绒毛状霉斑"差距很大）。

两个关键选择：

| 选择 | 为什么 |
|---|---|
| **avg + max 双池化** | 霉斑平均只占 2.8% 面积。全局平均池化会把这点响应摊薄到 1/36，而最大池化只关心"最强的那个位置有没有异常"。这是小缺陷检测的常规做法（类似 MIL 里的 max-pooling 聚合）。 |
| **第 4 块用膨胀卷积** | 14×14 特征图上一个 3×3 卷积的感受野只有 3 个像素尺度；dilation=2 把它扩到 5，让最后阶段能看到"一片菌落簇"而不是单个斑点。 |

### 训练配置

| 项 | 取值 |
|---|---|
| 损失 | CrossEntropy + label smoothing 0.03 |
| 优化器 | AdamW，lr 1.2e-3，weight decay 1e-3 |
| 调度 | LinearLR warmup（10% 轮次）+ CosineAnnealing |
| batch | 32（drop_last） |
| 输入 | 224×224（288 缓存 → 随机裁剪 0.85–1.0 → resize） |
| 归一化 | mean 0.5 / std 0.25（四个通道统一） |
| 模型选择 | 单折抽检阶段按 `val_acc + 0.5·(val_auc − 0.5)` 取最优 epoch（用来定轮数）；全量重训阶段**不选**，取最后一轮 |
| 训练轮数 | 26（事先固定，余弦退火走完即停） |
| 推理 | 水平翻转 TTA（固定配置，未针对测试集调参） |

### 数据增广（numpy 级，避免依赖 torchvision）

随机裁剪缩放 **0.85–1.0**、水平翻转、垂直翻转、±12° 旋转、亮度对比度扰动（×0.88–1.14 ±12）、通道增益扰动（白平衡漂移）、高斯噪声（25% 概率，σ 1.5–5.0）、轻微离焦（15% 概率，σ 0.4–0.9），边缘 reflect 填充。

> **裁剪幅度为什么收紧到 0.85**：原来用 0.72–1.0，等于把画面裁到 52% 面积。霉斑平均只占 2.8%、且聚成 1–3 簇，裁掉一半画面有相当概率把主菌落簇整个切出视野——那就等于给"发霉"样本贴上了"正常"标签。这是本任务里最容易踩的标签噪声陷阱。

### 流程

1. 单折抽检（531/664 张原图训练、133 张验证，24 轮）→ 看最优点落在第几轮
2. 轮数取整后**事先固定**（26 轮），在全部训练集上从零重训
3. 余弦退火走完即停，**不按测试集挑 epoch**
4. 测试集评估一次（含水平翻转 TTA）

## 3.2 消融：两个退化版本

为了定位"哪一处改动带来了提升"，保留了两个中间版本：

| 版本 | 输入 | 池化头 | 先验通道 | lr / wd |
|---|---|---|---|---|
| `train_cnn.py`（v1） | 192 | GAP | ✗ | 2.2e-3 / 1e-2 |
| `train_cnn_v2.py`（v2） | 224 | avg+max | ✗ | 3.0e-3 / 5e-3 |
| `train_cnn_v3.py`（**主模型**） | 224 | avg+max | ✓ | 1.2e-3 / 1e-3 |

`train_cnn_v3.py --no-prior` 可以在完全相同的结构与超参下关掉第 4 通道，得到干净的"有无先验"对照。

## 3.3 基线：传统 OpenCV 手工特征 + 机器学习

### 特征（共 425 维）

| 特征族 | 维度 | 内容 |
|---|---|---|
| 颜色统计 | 72 | BGR / Lab / HSV 九通道的均值、标准差、三阶矩、5 个分位数 |
| 颜色直方图 | 216 | HSV 的 H(24)/S(16)/V(16)、H–S 二维 12×8、Lab a–b 二维 8×8 |
| **霉菌响应图 + 斑块** | 20 | 见下 |
| LBP | 64 | 8 邻域基本 LBP，按 4 位归并成 64 bin |
| GLCM | 24 | 8 级量化，0°/45°/90°/135° 四方向 × (对比度/同质性/能量/相关性/绝对差均值/熵) |
| Gabor | 24 | 4 方向 × 3 波长，取响应均值与标准差 |
| 梯度 | 5 | Sobel 幅值均值/标准差/95 分位、Canny 边缘密度、Laplacian 方差 |

### 霉菌响应图（这一族的思路值得单独说）

手工特征要有效，必须把领域先验写进特征里。这里的先验和 3.1 的第 4 通道完全相同：

$$
m = \text{clip}\big(0.55\,\tfrac{\bar b^* - b^*}{32} + 0.30\,(1-\tfrac{S}{\bar S + 25}) + 0.40\,\tfrac{\bar L - L}{55},\ 0,\ 1\big)
$$

对 $m$ 在 0.30 / 0.45 / 0.60 三个阈值下做形态学开运算 + 连通域分析，提取斑块数量、总面积占比、最大斑块面积、前 5 大斑块平均面积，再加上 $m$ 本身的统计量。**这就是一个"手写版的霉菌检测器"**。

### 分类器选择

5 折分组 CV 上比较 4 个候选，按 F1 选优：

| 分类器 | 关键超参 |
|---|---|
| SVM-RBF | C=8，gamma=scale，class_weight=balanced，StandardScaler |
| RandomForest | 500 棵，min_samples_leaf=2，max_features=sqrt |
| ExtraTrees | 500 棵，min_samples_leaf=2 |
| LogisticRegression | C=0.5，max_iter=3000 |

## 3.4 为什么这两个模型值得对比

不是为了证明"深度学习更好"，而是为了回答工程上的真问题：

- **传统方法能不能先上线？** 它训练只要几分钟、可解释、不需要 GPU、误判原因能追溯到具体特征。如果它能到 90%+，很多产线场景根本不需要上深度学习。
- **CNN 多出来的那几个点，来自哪里？** 如果差距集中在"小面积、低对比度"的样本上，说明 CNN 学到的是**绒毛状局部纹理与簇状空间结构**，而这正是 LBP/GLCM 的全局直方图统计丢失的信息。这决定了后续该往哪个方向投入。
- **两者的失败模式是否相同？** 见 [`04-results.md`](04-results.md) 的交叉对照表：若分歧样本多，融合（CNN 概率 + 手工特征喂进 GBDT）往往能再涨 1–2 个点，且推理成本可控。
